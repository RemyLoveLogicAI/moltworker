## Overview

This Bash startup script prepares and launches the Moltbot gateway in a containerized Cloudflare environment. On start it checks whether a gateway is already running and, if not, decides whether to restore configuration and skills from a mounted R2 backup by comparing remote and local .last-sync timestamps. If a valid backup is found it copies the configuration and skills into the local config layout; otherwise it ensures a baseline config exists by copying a template or writing a minimal default.

After ensuring a config file is present, the script runs an embedded Node.js snippet that reads /root/.clawdbot/clawdbot.json, mutates it according to many environment variables (gateway auth, channels, TTS/STT, model providers, memory/vector stores, tools, personas, and Cloudflare integration), and writes the updated JSON back to disk. The Node snippet logs which providers and channels were enabled but avoids printing secrets.

Finally the script removes stale lock files and execs the clawdbot gateway process with appropriate flags. The script uses set -e for fail-fast behavior and intentionally keeps the gateway token out of CLI args so it does not appear in process listings.

## Architecture Notes

- Startup pattern: Bash wrapper performs environment-aware initialization, delegates JSON mutation to embedded Node.js, then replaces the shell with the gateway process via exec.
- Restore decision: Uses .last-sync timestamp comparison between $BACKUP_DIR and local config; parsing fallbacks ensure conservative behavior.
- Security decision: Gateway token is set in config/environment, not passed on the CLI, to avoid exposure in process listings.

## Usage Examples

### Fresh instance with R2 mounted and newer backup

When $BACKUP_DIR/.last-sync is newer than /root/.clawdbot/.last-sync the script restores the backup into /root/.clawdbot, restores skills to /root/clawd/skills if present, runs the Node snippet to apply environment overrides, and then starts the gateway.

### Start with no R2 present and no existing config

If no backup is available the script creates /root/.clawdbot, copies a template if present or writes a minimal config, runs the Node snippet to enable providers based on environment variables, and then launches the gateway.

### Dev start with CLAWDBOT_GATEWAY_TOKEN set

Set CLAWDBOT_GATEWAY_TOKEN in the environment; the Node snippet ensures config.gateway.auth.token is set. The gateway is started without passing the token on the command line.

## Maintenance Notes

- set -e causes early exit on any failing command; wrap non-critical operations if tolerant startup is desired.
- Ensure .last-sync uses an ISO-compatible format since date -d parsing is locale-dependent.
- Protect backups and /root/.clawdbot permissions to avoid leaking sensitive API keys stored in config.
